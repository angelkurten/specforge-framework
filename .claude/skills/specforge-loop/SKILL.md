# Run the loop

1. Read `specforge/core/loop.md`. It is the whole rule; this skill only runs it.
2. **Red.** From the contract's Acceptance evidence, write one failing test per scenario. A test over prose checks each listed item by a phrase only that item carries; a needle such as "bound" or "control" also matches neighbouring text and lets the item vanish unnoticed (change 2026-10-25-v2-adjustments). It also asserts each section's body, not only its heading: a loop agent once filled two sections with placeholders that heading checks passed (change 2026-10-25-migration-guide). Run them and confirm every one fails for the expected reason. A premise about existing tests checks every assertion they make on the behaviour being changed, status and body, not only the status code (pilot change 2026-10-25-team-task-statuses blocked on an export test's body). Before Red, grep each file in Scope across the existing suites (`grep -rln <file> scripts tests tools/cli/tests`) and add a premise for every constraint they place on it; a locked test once required a README link that a conformance test forbids, and only CI found it (change 2026-10-25-migration-guide). A test of release or dated text reads the version from `VERSION`, as PRD-016's conformance rows do, or stays out of permanent CI: a test pinning `[Unreleased]` or `0.28.0` breaks the next release (change 2026-10-26-release-0-28-0). When the change adds a path or ref argument, the red tests cover an absolute path, a subdirectory, a symlink, an invalid value and an empty one; review found all five on `review_prep.py --repo` after Red had covered none (change 2026-10-26-sibling-repos). When a change moves where paths live, grep every `specforge/scripts/*.py` for its path checks before writing the premises: the sibling Explore checked four of the five scripts, and `compose_check.py` refused the first real sibling's compose (change 2026-10-27-compose-siblings).
3. Before asking, scan the contract and the test files for literal invisible characters (`python3 -c` over `unicodedata.category(c) == "Cf"`); the file tool can decode a typed `\u` escape into the character itself (change 2026-10-25-invisible-chars). Show the human the list of tests and ask, as one question, whether to approve them. Do not write implementation code before the answer.
4. On approval, lock them: `python3 specforge/scripts/lock_tests.py approve <change> <test files>`. Create `<change>/progress.md` from `templates/progress.md`, with the budget from the contract's Stop and escalate section and one task per test. Order the tasks by what each test calls, not by scenario number: a test that uses a route another task introduces goes after that task (pilot change 2026-10-25-team-task-statuses blocked on iteration 1).
5. **Green.** Run `python3 specforge/scripts/loop.py <change>`, or tell the human the command if this session should not run it. Report the exit line verbatim.
6. On exit 4 or 5, stop and show the human the reason; never edit a locked test to get past it.
